# Design

## Context

Сейчас размер страницы разбирается в `css.ParsePageSize` как имя (`A4`, `A5`, `Letter`) или две длины; запасной размер из параметров запуска применяется позже в `layout.ParsePageStyle`, который знает только `size` целиком. Стили собираются `profile.ExtractStyleSheets`: обход DOM, текстовые узлы `<style>`, смещения сдвигаются на позицию узла, а диагностика считает позицию через `doc.Position(offset)` — то есть всегда внутри HTML. `<link>` и `<script>` отсутствуют в белом списке элементов и отклоняются. Флага строгого режима нет.

См. `proposal.md` — мотивация и границы.

## Goals / Non-Goals

**Goals:**

- Ориентация страницы как часть грамматики `size`, согласованная с запасным размером запуска.
- Локальные таблицы стилей в порядке документа, с диагностикой, указывающей в подключённый файл.
- Предсказуемая политика скриптов: не исполнять, не рендерить, сообщать; в строгом режиме — отказ.
- Фикстура, которая проверяет пагинацию длинной таблицы.

**Non-Goals:**

- Сеть: удалённые стили и шрифты остаются запрещёнными.
- `@import` внутри CSS.
- Медиазапросы кроме `print` и `all`.
- Исполнение JavaScript и интерактив.
- Флаг ориентации в CLI (`-landscape`): ориентация задаётся документом.

## Decisions

### 1. Разбор `size` отдельно от разрешения ориентации

`css.ParsePageSize` возвращает не готовый размер, а разобранное описание:

```go
type PageSizeSpec struct {
    Base        PageSize // ноль, если размер не назван
    HasBase     bool
    Orientation Orientation // Any, Portrait, Landscape
}
```

`layout.ResolvePageSize(spec, fallback)` применяет ориентацию: при `landscape` стороны меняются местами, при `HasBase == false` берётся `fallback` из параметров запуска.

*Почему не передать fallback в парсер*: тогда `css` начинает зависеть от настроек запуска, а валидатор профиля — от них же, хотя проверке достаточно грамматики. Разделение оставляет `css` чистым слоем значений.

*Альтернатива*: резолвить в `engine` — но тогда `@page` перестаёт быть самодостаточным для `layout`, который строит margin boxes по уже готовому размеру.

### 2. Источник правила вместо смещения в HTML

Каждый `css.Stylesheet` получает собственный источник (`File`, `Src`, индекс строк) и умеет считать позицию по смещению. `Rule` и `Declaration` ссылаются на свой стилевой лист, а `profile` переводит это в `diag.Position`.

```
   <style> в HTML ---> Stylesheet{File: "", Locate: doc.Position}
   <link> из файла --> Stylesheet{File: "styles/print.css", Locate: локальный индекс}
                            |
                            v
                 rule.Sheet.Position(rule.Offset)
```

*Почему не считать `diag.Position` прямо в парсере*: `css` начал бы импортировать пакет диагностик и знать про HTML-документ. Ссылка на лист оставляет слои в текущем порядке зависимостей.

*Цена*: у правил появляется поле-ссылка, и все места, где раньше вызывался `doc.Position(offset)`, переходят на `rule.Sheet.Position`. Это механическая, но широкая правка тестов позиций.

### 3. Один упорядоченный обход вместо двух источников

`profile.CollectStylesheets(doc, opts)` обходит DOM один раз и возвращает `[]*css.Stylesheet` в порядке появления: `<style>` → разбор на месте, `<link rel="stylesheet">` → чтение файла и разбор. Движок передаёт срез в `css.NewCascade` вариадически, поэтому порядок каскада совпадает с документом без дополнительной сортировки.

*Почему не сливать в один лист*: слияние теряет границу файлов, а именно она нужна для позиций. Кроме того, срез позволяет позже кешировать разбор файла.

### 4. Правила для `<link>`

- `rel` без учёта регистра, только `stylesheet`; остальные значения (`icon`, `preload`, `canonical`) игнорируются без диагностики.
- `media`: пусто, `print`, `all` — применять; иное — пропустить лист целиком (не ошибка: это нормальная практика для печатных шаблонов).
- `href`: абсолютный или относительный путь к файлу. Схема `http`/`https` — ошибка `css/link-remote`, `data:` — ошибка `css/link-unsupported`.
- Если задан `BaseDir`, разрешённый путь ДОЛЖЕН оставаться внутри него: проверка через `filepath.Rel` и отказ при `..` в начале. Абсолютный путь вне `BaseDir` отклоняется.
- Отсутствующий файл — ошибка `css/link-load` с путём; документ не собирается.

*Альтернатива*: разрешать сеть с белым списком хостов — исключено: движок принципиально не делает сетевых запросов, это часть его контракта.

### 5. Политика скриптов

`<script>` не входит в белый список элементов и не становится боксом: в таблицу стилей движка добавляется `script { display: none }`, а `profile` при обходе элементов выводит предупреждение `html/ignored-script` вместо ошибки. Содержимое скрипта уже не попадает в дерево как разметка — парсер отдаёт его как raw text.

*Почему не добавить `script` в белый список*: это выглядело бы как поддержка, тогда как движок лишь вырезает тег.

### 6. Строгий режим

`engine.Options.Strict bool` → `profile.Options{Strict: true}` → любое предупреждение становится ошибкой с тем же кодом и `Severity: Error`. CLI получает `-strict` у `validate` и `convert`.

*Почему все предупреждения, а не только скрипты*: один переключатель проще объяснить, чем список «строгих» кодов; к тому же `layout/overflow` в строгом режиме тоже должен валить сборку.

### 7. Фикстура большого документа

`testdata/bigtable.html`: 35 строк на 11 колонок, русский текст, шапка в `thead`, итоги в `tfoot`, `@page { size: A4 landscape }`. Пишется с нуля; документы из html-to-pdf-tests не копируются (у репозитория нет лицензии), они использованы только как ориентир на реальную форму.

## Risks / Trade-offs

- **Широкая правка позиций**: источник правил затрагивает парсер, каскад, валидатор и тесты. → Делать отдельным шагом до `<link>`, проверять существующие тесты позиций после каждого шага.
- **Тихая потеря скриптов**: шаблон с JS-графиком соберётся без графика. → Предупреждение в отчёте, `-strict` для CI; в `docs/profile.md` явно сказано, что JS не исполняется.
- **Обход `BaseDir`**: при пустом `BaseDir` ограничение не действует, и относительный путь резолвится от рабочего каталога. → Задокументировать: сервис обязан задавать `BaseDir`.
- **Ориентация без имени размера**: результат зависит от `-page`. → Явный сценарий в спеке и тест: `size: landscape` при `-page A5` даёт 210×148 мм.
- **Порядок стилей**: ошибка в обходе DOM даст неверный каскад. → Тест: `<style>`, затем `<link>`, затем `<style>` — побеждает последний.
- **Строгий режим меняет код возврата** для шаблонов с предупреждениями. → Только при явном `-strict`; поведение по умолчанию не меняется.
