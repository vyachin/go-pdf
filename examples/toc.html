1. Project goals

The project aims to build a document pipeline that produces invoices, acts and contracts without manual layout. The main goal is reproducibility: the same template and data must produce the same file.

A secondary goal is predictable pagination: running headers and footers, repeated table headers and keeping lines together must work without add-ons on top of the renderer.

2. Scope of work

The scope includes: parsing HTML and CSS within the profile, laying out blocks and tables, pagination, embedding fonts and producing a correct text layer.

Out of scope: arbitrary external HTML, JavaScript, flexbox and grid, and interactive forms.

3. Risks

The key risk is CSS profile growth. Every new property increases the testing surface, so profile changes go through a specification change rather than a commit to the table.

The second risk is fonts: a missing glyph must be an error, not a blank space in the document.

4. Plan

The plan is split into milestones: from a line of Russian text in a valid PDF to a table of contents with page numbers and bookmarks. Each milestone is a working slice, not half a layer.
